# Morning Exercise

A small exercise-habit app for a coffee walk past a Singapore fitness corner. The default routine uses a push-up platform, a pull-up bar and parallel bars. No floor work, pull-ups or dips.

## Experience

Open the app → see the workout → Start. No first-run setup or goal picker. A discreet edit button changes only the time ceiling; the default is two minutes.

The default is now two minutes. The first session has 20 seconds of preparation, up to three slow platform push-ups in a 15-second window, 25 seconds to rest and move, one small hanging knee raise in a five-second window, 25 seconds to rest and move, a three-second parallel-bar support hold, then 27 seconds of rest. Complete only the prescribed reps and rest for the rest of each window; no continuous repetitions to fill the timer. Hands are elevated on a high, stable platform, with feet on the ground. For the knee raise, bend the knees and make a small controlled curl without swinging. If it is too hard, use the familiar plain hang for up to three seconds instead. No pull-ups, dips, floor work, jumps or drops.

After a visit, **Back to workout** returns directly to the main screen. Effort feedback is optional; returning without a rating saves the visit as unrated (`skipped`) without inventing an effort score. An immediate cancellation before one elapsed second returns without a visit. Picking a rating also returns to the main screen. A completed day keeps the routine visible and offers **Start again**, which resets the timer without deleting history or earning a second daily progression credit. Repeats use the existing recovery policy, so a strength visit is followed by an easy feet-down routine. New hard or pain feedback from a repeat can make the saved daily feedback more cautious, without adding another visit or repeatedly reducing a level. Major screen changes focus the new main region.

One-tap feedback guides the next visit. Strength days have a rest calendar day between them, at most three in seven days. Recovery days stay feet-down at the parallel bars, with no loaded holds, push-ups or knee raises. Three easy full visits over at least seven calendar days can advance a stage. Progression alternates a single additional push-up (maximum six) with a single additional second of support (maximum six). The knee raise stays at one attempt, with no automatic progression to straight-leg raises. Normal and recovery sessions use the selected time; the optional small session and the return after a week away last one minute. The time ceiling is never expanded.

Existing `personal-bars-v1` profiles migrate once to `personal-corner-v2`, resetting the dose and setting two minutes while preserving visit history. Current-program time preferences persist on subsequent loads. Browser-local storage does not sync between devices. The timer pauses when backgrounded or interrupted. Tapping Start unlocks a soft bell and bundled English trainer voice clips. A bell marks the beginning of the session, each phase boundary and completion. The voice says Get ready, Start, Rest and Workout complete, and counts the final five seconds of longer phases. Short phases prioritize their opening cue, then count the remaining seconds. Pause, guidance, End workout, a hidden tab and page navigation cancel pending cues. Resume restarts the current phase cue without replaying elapsed countdowns. The nine voice clips total about 30 KB and do not require installed device voices or a speech-service account. Browser speech is a fallback if clips cannot load. On Safari versions supporting the Audio Session API, Start and Resume select the playback session before opening Web Audio, avoiding the ambient route that iPhone Silent Mode can mute. Pause, page backgrounding and completion restore the previous session type after pending audio has ended. Older browsers continue with their existing audio behavior. Visual cues remain available; audible volume depends on device sound settings. Keep the app visible while exercising. The lime-green morning background moves gently between workouts. Use its header pause control to stop it; it also stays still during a workout, in a hidden tab, or when Reduce Motion is enabled.

Small 8-bit movement previews appear in the routine list. During a strength step, the same pixel-art man demonstrates the movement beside the timer. Push-ups cycle slowly once per five seconds; the knee raise plays once and settles into a plain hang; the parallel-bar support stays steady without dipping. Demo poses follow the existing workout clock, pause with it, and do not restart on resume. Reduce Motion shows a static pose. Preparation, recovery and rests keep their existing timer. Artwork was generated with the built-in image-generation tool; the original atlas and complete prompt are saved in `assets/sprites/` and the three transparent four-frame strips are in `dist/sprites/`.

These low repetition counts, short hold durations and progression thresholds are personal app heuristics, not a validated clinical prescription. Movement references: [NASM incline push-up](https://www.nasm.org/resource-center/exercise-library/incline-push-up) and [Catalyst Athletics hanging leg raise and scaling options](https://www.catalystathletics.com/exercise/45/Hanging-Leg-Raise/). Concerning pain or unusual symptoms mean stop; professional guidance is appropriate where needed.

## Development

```sh
node --test tests/*.test.mjs
node --check dist/app.mjs
python3 -m http.server 8791 --bind 127.0.0.1 --directory dist
```

Buildless HTML/CSS/JavaScript; no API keys, account system, analytics, GPS or uploads. Production: https://morning-exercise-sg.vercel.app — deployed to Vercel on 22 October 2026. The two-minute routine is available over HTTPS without the Mac or shared Wi-Fi. Source: https://github.com/febriy/morning-exercise. Vercel serves `dist/` using the root `vercel.json`. Deploy from this directory with `vercel deploy --prod`. The GitHub repository is connected to the existing Vercel project. Pushes to `main` automatically deploy to the production address; other branches receive preview deployments. `.vercel/` contains ignored local project linking. Progress is stored per browser and origin, so the hosted app starts with fresh local history rather than importing LAN-preview history.

Safari audio routing reference: [WebKit issue 251532](https://bugs.webkit.org/show_bug.cgi?id=251532), including its recommendation to select `navigator.audioSession.type = "playback"`. The regression fixture models the documented Silent Mode routing behavior; it does not substitute for an audible check on a physical iPhone.
